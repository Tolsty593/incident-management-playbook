# Incident Management Playbook

A practical collection of incident management procedures, escalation processes, communication templates, and root cause analysis documentation.

## Purpose

This repository showcases operational support and incident management practices used to restore services quickly while maintaining clear stakeholder communication.

## Key Areas

- Incident Management
- Major Incident Coordination
- Escalation Management
- Stakeholder Communication
- Root Cause Analysis
- Continuous Service Improvement

## Repository Contents

| Document | Description | When to use it |
| --- | --- | --- |
| [Major Incident Process](MajorIncidentProcess.md) | End-to-end incident lifecycle in six phases, with roles and outputs | From the moment a major incident is suspected |
| [Escalation Guide](EscalationGuide.md) | Severity definitions, escalation matrix and handover checklist | When setting severity and deciding who to involve |
| [Communication Templates](CommunicationTemplates.md) | Ready-to-use incident notifications and updates | Each time an update is due |
| [Root Cause Analysis Template](RootCauseAnalysisTemplate.md) | RCA framework using the 5 Whys, with a worked example | After service is restored |
| [Post-Incident Review Template](PostIncidentReviewTemplate.md) | Agenda and template for a blameless lessons learned review | Within a few days of the incident |

## How the Documents Fit Together

**During the incident**

1. Follow the [Major Incident Process](MajorIncidentProcess.md) from detection to resolution.
2. Use the [Escalation Guide](EscalationGuide.md) to set the severity and bring in the right people.
3. Send updates using the [Communication Templates](CommunicationTemplates.md).

**After the incident**

4. Record why it happened in the [Root Cause Analysis Template](RootCauseAnalysisTemplate.md).
5. Review how it was handled using the [Post-Incident Review Template](PostIncidentReviewTemplate.md).
